# oc-web-client

> Omni Com 的可选浏览器客户端。它通过 WebSocket 与 Java 服务器对话，只使用 DOM、Canvas 2D 与 WebCrypto，不依赖前端框架。

## 并行工具链

这个仓库的 Java 侧与 Web 侧是**完全并行**的两套工具链，谁也不调用谁：

| | Java 侧 | Web 侧 |
| --- | --- | --- |
| 构建工具 | Gradle wrapper（`gradlew` / `gradlew.bat`） | pnpm |
| 第三方依赖 | **零**；只用 JDK 17 与 JPMS | `typescript`、`vite` 两个 devDependencies |
| 网络 | 不需要；`./gradlew build --offline` 可构建并跑自校验 | 第一次 `pnpm install` **需要网络**；之后可离线 dev/build |
| 谁调用谁 | Gradle **从不**调用 npm 或 pnpm | pnpm **从不**调用 Gradle |

如果 `pnpm install` 打印 `[ERR_PNPM_IGNORED_BUILDS] Ignored build scripts: esbuild`，那是 pnpm 10 默认拦截依赖的生命周期脚本，不是失败：esbuild 的平台二进制也会以可选平台包的形式送达，所以客户端能正常运行。`package.json` 里的 `pnpm.onlyBuiltDependencies` 字段显式放行这一个脚本，从而让这条警告（以及 `--frozen-lockfile` 的 CI 运行）保持安静。

由此得到两条硬规则：

1. `./gradlew build --offline` 必须始终是绿的，且它的输出与 `web-client/` 无关；没有 `node_modules` 也照样能构建 Java。
2. Web 客户端坏了、没装、没网，都不会影响 Java 侧；反过来 Java 服务器没起，也只会让这个页面连不上。

## 前置条件

| 需要 | 版本 |
| --- | --- |
| Node.js | 18+（Vite 6 的要求；建议 20+；`pnpm check:render` 直接执行 TypeScript，需要 24+） |
| pnpm | 9+；`package.json` 里写的是 `packageManager: "pnpm@9"` |
| 浏览器 | 支持原生 ES modules、WebSocket、WebCrypto 的现代浏览器 |

依赖范围固定在 `package.json` 里：`typescript` **^6.0.3**，`vite` **^6.0.0**（解析到 Vite 6.x）。

## 跑起来

先启动 Java 服务器，并确认它在 `25567` 上提供 `/ws` 与静态页面（启动方式与端口以服务器文档和启动输出为准：
[oc-game-server 快速上手](../projects/oc/oc-game-server/help/01-getting-started.md)）。

```shell
cd web-client
pnpm install
pnpm dev
```

打开 Vite 打印的地址（通常是 `http://localhost:5173/`）。页面上的**主机与端口都留空**时，客户端连接同源的
`/ws`，由 Vite 的 dev proxy 转发到 `ws://127.0.0.1:25567`；填上主机与端口则直连。同一条 dev proxy 也把
`/plugin-assets` 转发到 Java 服务器，所以开发时贴图同样来自插件，而不是 `public/`。同一条 dev proxy 也把
`/world` 转发到 Java 服务器，游戏画面因此能轮询真实的 `GET /world/snapshot`。

连接成功后页面会先发 `HELLO 1`，并且只在收到 `OK OC/1` 时启用命令按钮。然后：

1. 填用户名与密码，点 `REGISTER` 创建账号（注册不会登录），再点 `LOGIN`；成功后 `REQ` 才可用。`LOGIN` 成功后页面会自动发 `WHOAMI`，把引擎玩家 id 存下来并显示在 HUD 上；游戏操作面板用这个 id 做归属检查。
2. 把服务器的 `data/oc-debug/debug.key` 内容粘进 `debug.key` 文本框。
3. 点 `engine-info`：页面用 `INFO json` 封一个信封，发 `REQ engine-info <base64>`，再打开回答并格式化 JSON。
4. 在 `hello` 名字框里填一个名字（默认 `world`），点 `hello`：页面发 `REQ hello <base64(UTF-8 名字)>`，
   把回答的 base64 解码成 UTF-8 文本显示在 toast 与日志浮层里。这需要先按下一节安装 `oc-hello` 插件。
5. `PING`、`COUNT` 与 `QUIT` 按协议表工作。

创建账号只有两步：先点一次 `REGISTER`（用户名 3-32 个字符，只能用字母、数字、`_`、`.`、`-`；密码至少 6 个字符，两条规则都由服务器校验），再点 `LOGIN` 登录；注册成功**不会**自动登录。服务器回答 `OK …` 表示账号已建好；重名会回答 `ERR …`，页面把服务器给出的消息原样显示在状态行、错误 toast 与日志浮层里。

OC/1 只使用文本帧。若服务端发来二进制帧，页面只记录一行“服务端发来二进制帧，已忽略（协议只使用文本帧）”，
**不关闭连接**，也不丢弃还在等待回答的命令；这与服务端“回 `ERR binary frames are not commands` 并保持连接”
的行为一致。

**心跳。** 连接可用时，页面每 20 秒通过与其他命令相同的按序队列发送一次 `PING`（常量 `HEARTBEAT_MS` 在
[`src/heartbeat.ts`](src/heartbeat.ts) 里），服务器回答 `PONG`，两条作为一个交换出现在日志浮层和 toast 里。定时器只在 `HELLO 1` / `OK OC/1`
握手成功之后才启动，上一个 `PING` 没回答完不会再排一个；关闭连接和重连之前都会清掉它。这样空闲页面就不会被
WebSocket 的空闲超时切断（`/world/snapshot` 是普通 HTTP，不会刷新 WebSocket）；`PING` 按钮仍然是手动单次。

## toast 控制台与日志浮层

常驻的协议日志面板已经移除。每个命令/回答交换现在是右下角的一条 toast：上面一行是发出的命令（`→`），下面一行是
回答（`←`），两行都折叠成单行，所以一次交换恰好占一到两行。普通 toast 约 **4 秒**后消失；错误 toast——`ERR ...`
回答，或“先 LOGIN”这类客户端拒绝——约停留 **8 秒**，只用亮度与字重区分（白色边框、加粗白字），因为页面外壳是灰阶的。
最新的 toast 在最上面，最多同时可见 **5** 条，第 6 条进来时最旧的一条被丢弃。群体命令只用一条 toast，命令与回答
两半各自用 ` · ` 连接每个单位的行。由快照差分派生的事件（`建筑完成：…` / `遭到攻击：…`）也走同一条普通 toast
（没有命令半行），并同样写入历史。

什么都不会丢：协议面板顶部的小 **日志** 按钮会打开一个全屏历史浮层，里面按顺序列出原来的 `#log` 文本。它有
**关闭**与**清空**两个按钮（清空会同时清掉历史与当前 toast），按 `Esc` 或点背景也能关闭，关闭后焦点回到按钮。
状态行、连接表单、HUD、游戏操作面板以及 TypeScript 绑定的每一个元素 id 都保持不变。

## 游戏画面

页面左侧是整块 Canvas 2D 世界画面，右侧（窄屏时在下方）是原来的协议面板；`connect`、`REGISTER`、`LOGIN`、`PING`、`COUNT`、`engine-info`、`hello`、`QUIT` 命令本身不变，它们的交换以 toast 呈现，完整历史仍可从 **日志** 按钮打开。不需要安装新依赖：仍然是 `typescript` 与 `vite` 两个 devDependencies。

```shell
cd web-client
pnpm dev
```

打开 Vite 打印的地址即可；Java 服务器没起也能看画面，只是协议面板连不上。右侧协议面板顶部的
**隐藏游戏画面 / 显示游戏画面** 按钮会把 Canvas 收起，让协议面板占满整页；toast 与 **日志** 浮层在两种视图下都能用。

**单色界面。** 页面外壳——面板、按钮、标题、HUD 芯片、协议日志、游戏操作面板、小地图边框与状态行——刻意只用灰阶，没有任何色相；错误状态是亮白文字配白色左边条，而不是红色。Canvas 是例外：它属于游戏内容，因此保留自己的颜色；小地图的地形、归属圆点和白色相机框，以及建造预览的绿/红/琥珀色格子也一样。所有悬浮表面还都是**半透明**的：侧面板、HUD 芯片、小地图面板、仓库面板、悬停提示框、toast 与日志浮层面板统一使用 `rgba(0, 0, 0, 0.72)` 的黑色底、1 像素灰边框，没有模糊也没有光晕（`backdrop-filter: none`），所以游戏画面始终能从它们后面透出来。这些表面的文字是 `#e6e6e6` 或白色，即使压在最亮的地形上也保持至少 7:1 对比度；同时没有任何东西给 Canvas 加遮罩或滤镜——日志浮层的容器本身是透明的，只有它的面板变暗。站点图标来自 [`oc.png`](public/oc.png)（由仓库根目录的 `oc.png` 原样复制），由 `index.html` 的 `icon` 与 `apple-touch-icon` 链接引用。

HUD 固定在画面左上角，实时显示：

- 世界来源：快照正常时显示 `世界：server · tick 42`，使用内置占位地图时显示 `世界：demo`；
- 快照窗口的原点与相机坐标：`坐标：-1234,-567 · 窗口：-1250,-582`。两者都可以是负数，并随着镜头平移持续计数；镜头流入新窗口时窗口原点会变。占位地图上初始显示 `坐标：22,16 · 窗口：0,0`（占位岛屿自己就是一个原点为 `0,0` 的窗口）；
- 贴图来源：`atlas · oc-hello`（最多三个插件时列出插件 id）、`atlas · 4 plugins`；回退到程序化绘制时显示 `procedural`；
- `WHOAMI` 回答的引擎玩家 id（`玩家：3`；未登录时 `玩家：—`，每次重连都会清空）；
- 当前玩家的资源与收入速率，取自 `players` 里 id 等于 `WHOAMI` 回答的那一行：`资源：alice · 金 300 (+30/分) · 木 60 (+20/分)`。速率后缀来自 `goldPerMinute` / `woodPerMinute`；旧快照没有这两个字段时整个后缀省略，新服务器报告 0 时仍显示 `+0/分`，操作员因此能看出当前没有矿场在工作。世界里还没有这一行时（未登录、占位地图，或旧服务器的快照没有 `players` 字段），资源行变灰并显示破折号（`资源：金 — · 木 —`）；
- 鼠标下的瓦片坐标；
- 缩放倍率（0.5× 到 2.5×）；
- 平滑后的 FPS；
- 恰好选中一个实体时，显示它的 id、显示名、归属标签与地面坐标（`选中：e12 普通 [我] (12.5, 8.5)`）；标签是 `我`（自己）、`敌`（其他玩家）或 `中立`（没有主人，或 `WHOAMI` 还没回答）。贴图清单里没有这种 kind 的名字时回退到原始 kind（`选中：e12 unit.melee.t1 [中立] (…)`）；没有选中时显示 `选中：无`。选中多个单位时同一个芯片显示 `已选：3 个单位`，单实体详情与建筑芯片会隐藏；
- 恰好选中一个建筑时（不论敌我），显示它的显示名与 id（`建筑：兵工厂 1 级 #42`），没有名字时回退到原始 kind（`建筑：building.armory.t1 #42`）。快照带尺寸时芯片追加 `· 尺寸：3×3`；建筑在建时还会显示一个小内联进度条与完成百分比（`▮ 42%`）。选中仓库时还会追加库存，例如 `· 库存：金 120 · 木 40`，只显示正数，顺序固定为金、木。没有 `w`/`h`/`progress`/`contents` 的旧快照（或占位地图）直接省略这些内容；
- 选中建筑时，在建筑芯片下方为队列里每个未完成任务画一行：清单显示名（清单没有名字时用原始 `kind`）、一条细的 `ticks / total` 进度条，以及从 1 开始的 `i/n`（`普通 ▮▮▯ 1/2`）。尚未开工的任务 `ticks === total`，所以进度条从空开始。Canvas 上原有的 `生产中 ×N` 标记保持不变；只有 `queue` 而没有 `queueItems` 的旧快照只显示该标记，不画逐项列表。

**双击选中同类。** 双击作用于整个已载入窗口，而不只是点中的实体。双击单位时，选中被替换为**所有自己的、kind 相同、且地面瓦片位于已载入窗口内的单位**（和渲染器、拾取器共用的可见规则）；双击建筑（自己的、敌人的或中立的）时只选该建筑。双击总是替换选中，从不合并。拖拽绝不算双击的一半：结束框选的鼠标松开、或任何拖拽之后紧跟的单击都不会补成双击；两次单击必须落在同一目标上、间隔不超过 350ms、位移不超过 6px。

**悬停提示框。** 游戏画面可见且指针停在一个实体上时，光标旁会出现一个小提示框。它是 DOM 元素而不是 Canvas：显示清单里的显示名、归属标签（`我` / `敌` / `中立`）、生命百分比，建筑还追加快照报告的足迹（`尺寸：3×3`）与队列摘要（`生产中 ×N`）。它和其他外壳一样是灰阶半透明，设置了 `pointer-events: none`，绝不抢点击；框选或 BUILD 放置模式期间隐藏，并且始终夹在浏览器窗口内（靠近边缘时会翻到光标左侧或上方）。没有 `health` / `w` / `h` / `queue` 的旧快照直接省略对应部分，不编造数值。

**由快照差分派生的事件。** 服务器没有事件流，所以客户端比较前后两份快照：一个之前未完工（`progress !== 1`）、现在报告 `progress === 1` 的建筑会弹出 `建筑完成：<名称>`；一个属于玩家的实体生命比例下降至少 10 个百分点时会弹出 `遭到攻击：<名称>`。只比较两帧都存在的实体，且同一实体五秒内只产生一次事件，所以一场持续掉血的战斗不会每 500ms 轮询都弹一次。这完全在客户端完成，协议与服务器都不变。

**仓库面板。** 画面右上角有一块小的**只读**仓库合计：把所有自己的建筑的 `contents` 按物品相加，用显示名标注，并按名称排序。没有自己的仓库时显示 `未发现自己的仓库`；空仓库显示空合计。面板只读取快照，不增加“标记资源”或资源选择功能——服务器没有这两种东西，客户端也不应凭空发明。

**工兵快捷键。** 游戏操作面板的 `工兵` 按钮和 `O` 热键会选中已载入窗口内所有自己的 `unit.engineer`，并替换当前选中。快照没有订单或忙碌状态，无法区分空闲工兵与正在工作的工兵：按钮刻意叫 `工兵` 而不是 `空闲工兵`，它选中所有工兵，而不只是空闲的。

**归属环。** 每个实体脚下还有一圈细的地面环：`playerId` 等于当前玩家时是蓝色 `#3b82f6`，其他玩家是红色 `#ef4444`，没有主人、`playerId` 为 0 或还不知道 `myPlayerId` 时是灰色 `#9ca3af`（整张占位地图就是这种情况）。金色选中环保持不变，画在归属环之后、始终在最上层。分类规则在 `src/render/view.ts`（`ownershipOf`、`ownershipColor`），所以地面环和 HUD 标签不会给出不同答案。

**建造放置预览。** BUILD 武装后，页面在真正点击之前就预览光标下的整块足迹：宽高按建筑 kind 查表（客户端不认识的 kind 一律按 **3x3** 处理，表在 `src/render/placement.ts`，与经典目录保持一致），光标所在瓦片就是足迹左上角，每个足迹格画成三种状态之一：

- **可建造**：绿色描边 + 25% 填充；
- **被阻挡**：红色描边与填充——该格在快照里不是可建造地形（只有 `grass` 与 `sand` 可建）、在已载入窗口之外，或已被某个实体的足迹覆盖；
- **超出工兵范围**：琥珀色描边与填充——工地离选中的工程师太远。

悬停时状态行直接给出结论：`可建造`、`地形不可建`、`位置被占用`、`超出工兵范围 16 格` 或 `超出已载入窗口`。预览和点击共用同一个纯判定（`buildPlacementPreview`）：**只有可建造的位置才会发出 `BUILD`**；非法位置点击会保持放置模式，并在状态行、日志和错误 toast 里报告原因，不发送任何命令。三种状态按 **blocked > out-of-reach > legal** 的顺序合并。射程判定是客户端对服务器规则的近似：服务器要求到足迹外一圈可走格的**路径**不超过 16 格（`CommandService.MAX_BUILD_PATH_TILES = 16`），而客户端只有快照，没有寻路，只比较工程师瓦片到足迹矩形的 Chebyshev 距离——16 格以内算可达，17 格算超出。这个近似可能接受一个被障碍物挡住的工地，但不会因为距离而拒绝服务器本会接受的工地；服务器仍然是最终裁判。预览颜色属于画布内容，和归属环一样；周围的界面外壳仍是灰阶。

**小地图。** 游戏画面左下角是一块固定的 **180x180** 小地图，由它自己的小画布绘制。面板外壳是灰阶（1 像素灰边框、`rgba(0, 0, 0, 0.72)` 半透明黑底），并且只有它自己的一块画布接收指针输入，所以画面其他区域的鼠标、滚轮与键盘操作完全不受影响；游戏画面上没有遮罩，也没有滤镜。面板里，已载入窗口的地形按**一瓦片一像素**绘制（离屏画布按瓦片尺寸画好后关闭插值放大），窗口内的每个实体是一个 **2x2 圆点**，颜色沿用地面环的归属规则（自己是蓝色、敌人红色、中立灰色），相机可见矩形是**白色 1 像素描边**。在小地图上**点击或拖动**即可移动镜头：落点先减去信箱偏移、除以每格像素数并**向下取整**，再加上有符号的窗口原点，所以负世界坐标同样精确；镜头居中到该格的格中心，目标点再夹到相机自己的 ±500000 瓦片数值安全边界上。地形图只在窗口或地形变化时重建，圆点与相机矩形则每个动画帧都重画。

**服务器世界。** 游戏画面不再只有内置的占位岛屿。画面可见时，`main.ts` 每 500ms 轮询一次
`GET /world/snapshot?cx=<相机 tileX>&cy=<相机 tileY>&r=32`（上一次请求未完成就跳过），并把最近两帧快照保留为动画循环的插值输入（见下文的**移动平滑**）。服务器世界是**无界**的：一份快照只携带一个方形窗口，`originX` / `originY` 是窗口左上角的绝对瓦片，`width` / `height` 是**窗口**大小，实体坐标仍是绝对世界坐标。文档里没有 `mapWidth` / `mapHeight`，也完全没有地图大小；窗口原点与每个实体坐标都可以是负数或很大的数。`src/render/view.ts` 的 `fetchWorldSnapshot(baseUrl, request)` 把服务器 JSON 转换成渲染器已有的 `WorldView`：地形内容路径变成地形 id，`originX` / `originY` 作为有符号整数保留，`health` 变成 `healthRatio`，`player` 变成 `playerId`，可选的 `players` 数组变成带类型的 `PlayerView` 行（没有这个字段的快照仍然合法，所以旧服务器照常工作）。实体细节字段同样是增量字段：`w` / `h` 变成 `footprint`，`progress` 变成夹到 [0,1] 的完成比例，`queue` / `queueTicks` 变成生产队列长度与当前任务的剩余 tick，`queueItems` 变成经过校验的 `kind` / `ticks` / `total` 任务数组（坏项被丢弃），仓库的 `contents` 变成只保留正整数的库存对象；玩家行的 `goldPerMinute` / `woodPerMinute` 保留为数字，旧服务器则保持 `undefined`。没有这些字段的旧快照照常转换，单个字段格式错误只会被忽略而不会让整个世界被拒绝。`terrainAt` 会把绝对瓦片减去原点（先向下取整，所以负的小数坐标会落进正确的格子），窗口外返回 `void`；渲染器与实体拾取都只在实体的瓦片位于窗口内时才绘制或选中它。行宽不符、字段缺失、坐标非有限值或窗口原点不是整数时整份文档被拒绝；但负数或很远的坐标**不是**错误，因为根本没有地图边界要跨越。确定性的 `demoWorld(seed)` 原样保留为缺少快照时的回退（例如 `--world off` 会回答 503）。标签页隐藏时 `visibilitychange` 会取消定时器，后台标签页不会继续请求；`--http-port 0` 时完全不会轮询，画面停在占位地图上。

**相机驱动的窗口流送。** 画面在移动，客户端跟着走：`main.ts` 维护一个相机焦点（相机中心的瓦片），一旦它进入已加载窗口边缘 8 格以内，就请求以该焦点为中心的新窗口，而不是把镜头平移进尚未加载的地形。新窗口到达之前旧窗口一直留在屏幕上，所以加载期间不会空白、不会闪烁；请求失败或被拒绝时保留最后一个窗口，不会退回占位地图；单调递增的请求 id 让迟到的回答输给更新的请求。请求的中心按原样发送，所以服务器对任意有符号中心都回答原点 `centre - r`：没有任何地图边缘会把窗口夹紧或向内平移。

**世界是无界的。** 客户端模型与相机里都没有地图宽、高或边界。相机只夹紧到一个非常宽松的 **±500000 瓦片安全边界**（32 像素/瓦片时是 1600 万世界像素）；这个边界不是玩法边界，而是因为引擎用单精度 `Vec2` 保存位置，到这个量级附近的分辨率已经只剩约一个世界像素。相机只在启动时构造一次，窗口到达时绝不重建：快照只改变加载了哪一片地形，不改变相机能去哪里。因此镜头可以朝任意方向一直平移，进入负坐标、越过出生点很远也不会被挡住。HUD 显示相机坐标与已加载窗口原点（`坐标：-1234,-567 · 窗口：-1250,-582`），操作员可以看到两者都变成负数并继续计数。

**移动平滑。** 快照每 500ms 才到一次，直接按快照绘制时单位就会一跳一跳。现在画面保留前后两帧服务器快照（各自是一个
转换后的 `WorldView` 加它的 tick），并在每个动画帧用 [`src/render/interpolate.ts`](src/render/interpolate.ts) 里的
`interpolate(previous, current, alphaFor(now, currentFetchedAt, WORLD_POLL_MS))` 重绘：两帧都有的实体按线性插值移动；
只在新帧出现的实体直接出现在新位置；只在旧帧出现的实体消失；两次轮询之间移动超过 4 格、或 kind / 归属发生变化的实体
直接吸附到新帧，不会在地图上滑过去。代价是晚一个轮询间隔：画面比最新快照落后一帧，这是服务器仍按 tick 发送绝对位置
（协议不变）时换取平滑的代价。演示世界不受影响：它没有快照，继续用自己的动画时钟。启动后的第一帧快照、以及流送到另一个窗口后的
第一帧快照都没有前一帧，直接原样绘制；标签页隐藏时轮询与动画循环都会停止。

### 操作

首次点击画面后生效，键盘事件只挂在 canvas 上，不会抢协议输入框的按键：

| 操作 | 效果 |
| --- | --- |
| 左键单击 | 用光标下的实体替换整个选中；点空地清空选中 |
| 双击单位 | 把选中替换为**已载入窗口内所有自己的同类单位**；同 kind 的敌方/中立单位与窗口外单位都被排除 |
| 双击建筑 | 把选中替换为仅该建筑，不论敌我。拖拽绝不算双击的一半，所以结束框选的松开、或拖拽之后的单击不会补成双击 |
| 悬停实体 | 在光标旁显示灰阶 DOM 提示框（名称、归属、生命、建筑足迹、队列摘要）；框选或 BUILD 放置期间隐藏 |
| Shift + 左键单击 | 把点中的单位加入选中，已在选中里则移除（建筑仍按替换处理，因为它没有群体命令） |
| 空地左键拖拽 | 画出框选矩形，选中所有“绘制位置”落在矩形内的**自己的单位**；矩形从画布空间换算成世界瓦片，所以负坐标同样正确。敌方、中立单位与所有建筑都被排除 |
| 从实体上开始的左键拖拽 | 仍然只选中该实体，不会变成框选 |
| 中键拖拽，或按住空格 + 左键拖拽 | 平移镜头。空地左键拖拽现在是框选，不再平移 |
| 右键空地 | 对**每个选中的自己的单位**发 `ORDER MOVE <id> <tileX> <tileY>`，每个单位一行 |
| 右键不属于自己的实体 | 对每个选中的自己的单位发 `ORDER ATTACK <id> <enemyId>` |
| 滚轮 | 以光标为中心缩放，光标下的瓦片保持不动 |
| 在小地图上点击或拖动 | 把镜头居中到落点所在格（按 floor 取整），并夹在相机的数值安全边界内。面板只占它自己的 180px 方块，其余区域的画面输入保持不变 |
| `WASD` / 方向键 | 平移镜头 |
| `+` / `-` | 以画面中心放大 / 缩小 |
| `F` | 复位镜头到起始位置并恢复 1× |
| `O` | 选中已载入窗口内所有自己的工兵（与 `工兵` 按钮相同）。快照没有订单状态，所以这是全部工兵，而不只是空闲工兵 |
| `Ctrl` + `1` … `9`（`Cmd` 同样可用） | 把当前选中编入该编队，替换编队原有内容。选中可以包含建筑；空选中会清空该编队 |
| `1` … `9` | 选择该编队。先剪掉世界里已不存在的实体 id；空编队在状态行报告 `编队 N 为空`，而不是静默清空选中。选中来自编队时，HUD 选中行带 `编队 N ·` 前缀 |
| `Shift` + `1` … `9` | 把当前选中加入该编队，保留编队原有内容 |
| `Esc` | 有 BUILD 放置模式时取消它；没有放置模式时取消选中 |

选中状态被所有命令路径共用：渲染器为每个选中实体画金色环；选中多个时 HUD 显示 `已选：N 个单位`；
只要选中里至少有一个自己的单位，游戏操作面板的 `STOP` 就可用，点击后对每个这样的单位发 `ORDER STOP <id>`。
编队也属于选中状态：纯规则 `assign` / `add` / `recall` / `prune` / `describe` 在
[`src/controlGroups.ts`](src/controlGroups.ts)，页面在每份快照到达时剪枝；编入编队不改变命令合法性——编队里可以
有建筑，但真正决定命令能否下达的仍是归属与单位检查。
左键仍然先经过放置模式：BUILD 已武装时，下一次在画面上左键单击会放置工地，不改变选中；该模式下空地左键拖拽
仍然平移镜头。

协议命令下面的**游戏操作**面板驱动剩下的语法。只有选中的实体属于 HUD 里的玩家 id 时（`entity.playerId === myPlayerId`）命令才可用，所以点中别人的单位不会误发命令；群体命令只作用于选中里自己的单位：

- `STOP` 对每个选中的自己的单位发 `ORDER STOP <selected>`；选中里至少有一个自己的单位时按钮可用。
- `工兵`（热键 `O`）是选择快捷方式，不是命令：它选中已载入窗口内所有自己的 `unit.engineer`。快照没有订单/忙碌字段，无法只选空闲工兵；按钮文字与它的 tooltip 都写 `工兵`，两份 README 也都说明了这一限制。
- 恰好选中一个自己的建筑时，面板按目录中的每条单位路径显示一个 `TRAIN <buildingId> <unitPath>` 按钮（`unit.melee.t1` … `unit.melee.t5`、`unit.engineer`）。有清单显示名时按钮文字就是显示名（经典单位是 `普通`、`强化`、`精英`、`将领`、`战王`、`工程师`），原始路径放在 tooltip 里；没有名字时回退到原始路径。当前兵营等级不够的单位也会显示，服务器回答的 `ERR ...` 会显示在状态行并弹出错误 toast。TRAIN/BUILD 两节只在恰好选中一个自己的建筑/工程师时出现。
- 恰好选中一个自己的工程师时，面板按目录中的每条建筑路径显示一个 `BUILD <engineerId> <buildingPath> <tileX> <tileY>` 按钮（`building.armory.t1`、`building.mine.t1`、`building.lumbercamp.t1`、`building.warehouse`）。按钮文字是清单显示名（`兵工厂 1 级`、`矿井 普通`，木材营地则使用清单给它的名字），没有名字时是原始路径。按下按钮进入放置模式：状态行显示模式，光标下的整块足迹按格预览（绿色可建、红色被阻挡、琥珀色超距）并在悬停时给出原因，只有**可建造**的位置才允许下一次在画面上左键单击发送命令，然后模式清除。非法位置点击会保持放置模式，报告 `地形不可建`、`位置被占用`、`超出工兵范围 16 格` 或 `超出已载入窗口`，不发送任何命令。`Esc` 只取消放置，不会取消工程师的选中。16 格判定是客户端对服务器 16 格路径规则的**距离近似**，详见上面的**建造放置预览**。

`LOGIN` 成功后页面自动发 `WHOAMI`（重新登录也会再发），把 `OK player <id>` 解析到 HUD 字段。每条游戏命令与回答都会出现在日志浮层与交换 toast 里（群体命令是一条 toast，里面把每个单位的命令与回答分别连接起来）；`ERR ...` 会变成错误 toast 并原样显示在红色状态行，成功则显示一句简短确认，确认里用显示名并把原始 id 放在括号中，例如 `已下训练 普通 (unit.melee.t1)` 或 `已在 20,40 下达 BUILD 兵工厂 1 级 (building.armory.t1)`。线路上的命令本身不变，仍然是 `unit.melee.t1` / `building.armory.t1`。目录在 [`src/commands.ts`](src/commands.ts)，注释说明服务器才是事实来源：服务器内容增加时这里也要同步。线路格式接收整数瓦片索引；引擎把 `GridPos` 当作该瓦片的中心。

**纹理由插件提供**：每个插件把 `assets/manifest.json` 和图片打进自己的 jar，服务器把它们合并成
`GET /plugin-assets/manifest.json`，客户端启动时读取并按 `atlasUrl` 加载每张图片。多个插件同时提供时按数组顺序
合并，**后者覆盖前者**（同名地形路径或实体 kind，显示名也一起覆盖）。本地 `public/textures/atlas.json` 不再是来源；这个目录只保留
[契约文档](public/textures/README.md)（清单格式、示例、脚底锚点、每种实体一行动画）。

清单还可以带**显示名**：实体的 `entities.<kind>.name` 与动画字段并列；地形瓦片用命名对象形式
`tiles.<path>: {"rect": [x, y, w, h], "name": "草地"}`，旧的数组形式仍然合法，只是没有名字。客户端把名字和帧一起
合并（后者覆盖前者），HUD、TRAIN/BUILD 按钮文字和成功状态/toast 行都会使用它；名字缺失或为空时一律回退到原始内容路径，
所以没有名字的清单行为与以前完全一样。名字只用于显示：协议命令仍然发送内容路径。
清单缺失、请求失败、图片载入失败或返回 `[]` 时，客户端自动退回程序化绘制：每种地形有独立颜色和细节，
单位是圆形、建筑是带屋顶线的方块，放大后还有 1 像素格线。同一遍绘制还会在建筑上方画灰阶状态：未完工时是一条
细的建造进度条（浅灰轨道、白色填充、1 像素描边），生产队列非空时是一个小的 `生产中 ×N` 标记；两者都位于屋顶之上，
不会盖住贴图。

> 初始地图由 `demoWorld(seed)` 生成，是确定性的占位岛屿；Java 服务器一旦能回答 `/world/snapshot`，画面就切换到
> 那个真实的引擎世界：一个无界世界，一次跟随相机加载一个 64×64 窗口；两边使用同一个 `WorldView` 形状，渲染层不需要改。

渲染数学与纯客户端规则（相机的负坐标向下取整与 ±500000 瓦片数值安全边界、以光标为中心缩放、占位地图确定性、
无界世界的有符号快照解析、负原点窗口平移、相机驱动的 8 格窗口触发、有符号窗口原点与请求排序、快照插值与吸附规则、
图集越界帧拒绝、清单显示名与原始 id 回退、磁盘上的经典清单、插件图集合并与回退、心跳常量与启动规则、框选矩形到
负瓦片范围的换算与“只选自己的单位”判定、Shift 加减选、toast 的生命周期/上限/错误色调规则、实体状态规则
（整数百分比、进度条比例、队列标记、尺寸标签、库存标签、在建判定与可选的 `footprint` / `progress` / `queue` /
`queueTicks` / `contents` 字段），包含 `building.lumbercamp.t1` 和 `building.warehouse` 的建筑目录，建造放置预览
（经典 3x3 足迹查表与未知 kind 的 3x3 回退、行优先足迹瓦片、实体列表占用判定、16/17 格射程边界、blocked >
out-of-reach > legal 优先级与五种原因文本），小地图（按比例布局、面板与世界瓦片的双向映射含负原点与 floor
语义、夹紧的镜头跳转），双击同类规则（只选自己、只选窗口内、建筑单独处理），工兵选择规则，提示框文本组成与
窗口夹紧，快照差分事件（10% 生命下降阈值与五秒按实体去重），以及仓库库存合计）可以离线检查：

```shell

```

[`scripts/check-render-math.ts`](scripts/check-render-math.ts)，逐行打印 `ok` / `fail`。脚本当前打印 256 项通过。

## hello 插件演示

`hello` 是示例插件 `oc-hello` 提供的请求，用来演示“插件回答请求”这一最小闭环。它不需要 `debug.key`，
但和所有 `REQ` 一样要求先 `LOGIN`。它只回答问候，不读写任何游戏状态。

构建插件 jar、放进服务器的插件目录、启动服务器，再启动浏览器客户端：

```shell
./gradlew --offline :projects:oc:oc-game-server-hello:jar
# 把 projects/oc/oc-game-server-hello/build/libs/oc-game-server-hello-2.0a.jar 复制到 plugins/
./gradlew --offline :projects:oc:oc-game-server:server
# 然后在 web-client/ 里：
pnpm install && pnpm dev
```

`oc-game-server-hello-2.0a.jar` 是模块 `version = '2.0a'` 的默认产物名；如果 Gradle 产出的名字不同，
以 `projects/oc/oc-game-server-hello/build/libs/` 里的文件为准。

这个 jar 还带着 `assets/manifest.json` 和一张 128x128 的 `assets/atlas.png`（8x8 个 16x16 单元格）：把 jar 放进 `plugins/`、启动服务器后，
浏览器画面会自动用这张图集渲染全部七条地形内容路径——`water`、`sand`、`grass`、`forest`、`hill`、`rock`、`void`。清单里有 20 个瓦片矩形（16 块美术瓦片，外加 `forest`、`hill`、`rock`、`void` 四个别名键），`entities` 为空，所以单位回退到程序化形状。插件资源从 jar 到服务器路由再到画面的完整链路，就是这一步在演示。
不需要往 `public/` 里放任何图片。

`plugins/` 是操作员的投放区：插件 jar 与它们的依赖 jar 都放在这一层，说明见
[`plugins/README.md`](../plugins/README.md)。插件生成的状态在服务器的 `data/` 下，不在 `plugins/` 里。
第一次 `pnpm install` 需要网络；装好之后的 `pnpm dev` 可以离线。

页面把名字按 UTF-8 编码再 base64（标准字母表，带 `=` 补齐）；服务器把请求载荷解码成原始字节交给插件，
再把插件返回的字节 base64 编码回送；浏览器最后把回答解码成 UTF-8 文本。`oc-hello` 自己不做 base64，
也不加任何信封。名字超过 64 字节时，插件会截断并加上省略号。

## 构建

```shell
pnpm build
```

`build` 执行 `tsc --noEmit && vite build`，产物在 `web-client/dist/`。Java 服务器在
`http://<host>:25567/` 提供这份静态文件。构建结束后可以用下面的命令本地预览：

```shell
pnpm preview
```

`pnpm install` 会生成 `node_modules/` 与 lockfile；`node_modules/`、`web-client/dist/` 与
`web-client/.vite/` 已在 `.gitignore` 里。首次安装需要网络，这是整个仓库唯一需要下载依赖的步骤。

## `debug.key`

- 服务器首次启用 `oc-debug` 插件时生成 `<数据目录>/oc-debug/debug.key`，默认是 `data/oc-debug/debug.key`。
- 内容是 64 个十六进制字符，也就是 32 字节的 AES-256 密钥；可以带一个结尾换行。
- 操作员**手工**把这份文件复制到浏览器所在的机器，再粘进页面上的文本框。密钥不通过 HTTP/WebSocket 下发，也不由页面生成。
- 服务器**永不覆盖**这份文件；删掉它再让插件重新生成，会让所有旧副本同时失效。
- 不要把 `debug.key` 提交进仓库、贴进 issue 或写进日志。
- `engine-info` 的信封有 60 秒防重放窗口，两台机器的时钟差超过 60 秒就会失败。

`engine-info` 使用 `crypto.subtle`。浏览器只在**安全上下文**里提供它：`http://127.0.0.1:25567/` 与
`http://localhost:5173/` 可以；直接用 `http://<局域网 IP>:25567/` 打开页面时通常不行，请用 localhost、
SSH 端口转发或 HTTPS 反向代理。

## 游戏命令与协议面板

协议面板仍然只提供 `PING`、`COUNT`、`REGISTER`、`LOGIN`、`REQ engine-info`、`REQ hello` 与 `QUIT`；
除了 `REGISTER` 会创建账号，这些命令都不修改游戏状态。单独的**游戏操作**面板发送服务器的游戏语法——
`WHOAMI`、`ORDER`、`BUILD`、`TRAIN`——它们**会**改变世界：命令让单位移动、战斗，`BUILD` 放置并支付工地，
`TRAIN` 排队训练单位。每条游戏命令都要求同一条连接已成功 `LOGIN`，并由服务器校验归属、实体是否存在、
所服务的内容以及玩家的库存。页面不会修改服务器配置、插件目录，也不会改账号密码或权限。

- `engine-info` 是 `oc-debug` 注册的只读报告；处理器不持有任何可写引用，报告由常量与临时对象拼成。
- `hello` 是 `oc-hello` 注册的只读问候；处理器只读取请求里的名字，不持有任何引擎、配置或网络引用。
- `REGISTER` 只创建新账号（重名会回答 `ERR …`），不登录，也不改已有账号的密码或权限。
- `LOGIN` 只在这条连接上标记身份，并刷新服务器记录的最近登录时间；它不改密码、不改权限，也没有改密入口。
- `WHOAMI` 按需分配并报告这条连接的引擎玩家 id；它本身不改变游戏状态。
