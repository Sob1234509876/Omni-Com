# oc-web-client

> Omni Com 的可选浏览器客户端。它通过 WebSocket 与 Java 服务端通信，只使用 DOM、Canvas 2D 和 WebCrypto，不依赖任何前端框架。

## 并行的两条工具链

本仓库的 Java 侧和 Web 侧是两条**完全并行**的工具链，彼此互不调用：

| | Java 侧 | Web 侧 |
| --- | --- | --- |
| 构建工具 | Gradle wrapper（`gradlew` / `gradlew.bat`） | pnpm |
| 第三方依赖 | **零**；只需要 JDK 17 和 JPMS | 运行时依赖 `katex`，加上两个 devDependencies：`typescript` 和 `vite` |
| 网络 | 不需要；`./gradlew build --offline` 即可构建并运行自检 | 第一次 `pnpm install` **需要网络**；之后开发/构建可离线 |
| 谁调用谁 | Gradle **从不**调用 npm 或 pnpm | pnpm **从不**调用 Gradle |

如果 pnpm install 打印 `[ERR_PNPM_IGNORED_BUILDS] Ignored build scripts: esbuild`，那是 pnpm 10 默认阻止
依赖生命周期脚本，并非失败：esbuild 的平台二进制也会以可选平台包的形式
到达，因此客户端可以运行。`package.json` 中的 `pnpm.onlyBuiltDependencies` 字段显式允许这一个脚本，
从而让该警告（以及 `--frozen-lockfile` 的 CI 运行）保持安静。

由此得到两条硬性规则：

1. `./gradlew build --offline` 必须始终通过，且其输出与 `web-client/` 无关；没有 `node_modules` 时 Java 侧照样能构建。
2. 损坏、缺失或离线的 Web 客户端永远不会影响 Java 侧；反过来，Java 服务端未运行只意味着本页面无法连接。

## 前置要求

| 要求 | 版本 |
| --- | --- |
| Node.js | 18+（Vite 6 要求；推荐 20+；`pnpm check:render` 直接执行 TypeScript，需要 24+） |
| pnpm | 10+；`package.json` 声明了 `packageManager: "pnpm@10"` |
| 浏览器 | 支持原生 ES modules、WebSocket 和 WebCrypto 的现代浏览器 |

依赖范围固定在 `package.json` 中：运行时 `katex` **^0.19.0**、`typescript` **^6.0.3** 和 `vite` **^6.0.0**（解析为 Vite 6.x）。

## 运行方式

先启动 Java 服务端，并确认它在 `25567` 上提供 `/ws` 和静态页面（如何启动以及端口由服务端文档及其启动输出决定：
[oc-game-server 快速开始](../projects/oc/oc-game-server/help/01-getting-started.md)）。

```shell
cd web-client
pnpm install
pnpm dev
```

打开 Vite 打印的地址（通常是 `http://localhost:5173/`）。当页面上的**主机和端口都留空**时，客户端连接同源的
`/ws`，由 Vite 开发代理转发到 `ws://127.0.0.1:25567`；填写主机和端口则直接连接。同一开发代理还会把
`/plugin-assets` 转发给 Java 服务端，因此开发期间贴图同样来自插件而不是 `public/`。该代理还会把
`/world` 转发给 Java 服务端，游戏视图正是通过它轮询实时的 `GET /world/snapshot`。

连接后，页面先发送 `HELLO 1`，只有收到 `OK OC/1` 后才启用命令按钮。然后：

1. 填写用户名和密码，点击 `REGISTER` 创建账号（注册不会登录），再点击 `LOGIN`；此后 `REQ` 才可用。`LOGIN` 成功还会自动发送 `WHOAMI`，保存引擎玩家 id 并显示在 HUD 中；命令栏和上下文面板用它做归属校验。
2. 把服务端 `data/oc-debug/debug.key` 的内容粘贴到 `debug.key` 文本框。
3. 点击 `engine-info`：页面用 `INFO json` 封装信封，发送 `REQ engine-info <base64>`，随后打开回复并格式化 JSON。
4. 在 `hello` 名称框中输入名字（默认 `world`）并点击 `hello`：页面发送 `REQ hello <base64(UTF-8 name)>`，
   把回复中的 base64 解码为 UTF-8 文本，并显示在提示消息和日志浮层中。这需要先安装下一节所述的 `oc-hello` 插件。
5. `PING`、`COUNT` 和 `QUIT` 按协议表所述工作。

创建账号只有两步：点击一次 `REGISTER`（用户名为 3-32 个字符，只能使用字母、数字、`_`、`.` 和 `-`；密码至少 6 个字符；服务端会校验这两条规则），再点击 `LOGIN` 登录；注册成功**不会**自动登录。服务端回复 `OK …` 表示账号已创建；重名会收到 `ERR …`，页面会把服务端给出的原话显示在状态芯片、错误提示消息和日志浮层中。

OC/1 只使用文本帧。如果服务端发送了二进制帧，页面只记录一行“服务端发送了二进制帧，已忽略（协议只使用文本帧）”，
**不会关闭连接**，也不会丢弃仍在等待回复的命令；这与服务端回复 `ERR binary frames are not commands` 并保持连接的行为一致。

**心跳。** 连接可用期间，页面每 20 秒发送一次 `PING`（[`src/heartbeat.ts`](src/heartbeat.ts) 中的 `HEARTBEAT_MS`），
走与其他命令相同的按序队列；服务端回复 `PONG`，两行都会作为一次交互提示出现在日志浮层中。
计时器只在 `HELLO 1` / `OK OC/1` 握手成功后启动，在有 `PING` 等待时绝不排队第二个，
并在关闭时以及重连前清除。这样空闲页面能挺过 WebSocket 的空闲
超时（`/world/snapshot` 是普通 HTTP，不会刷新套接字）；`PING` 按钮仍然是手动的一次性操作。

## 提示消息控制台与日志浮层

固定的协议日志面板已经移除。每次命令/应答交互现在都显示为右下角的提示消息，
位于**三区底栏之上**（整叠提示按底栏高度抬高，两者永不重叠）：一行显示
发送的命令（`→`），一行显示应答（`←`），都裁剪为单行，使整个交互最多占一两行。
普通提示约 **4 秒**后淡出；错误提示——`ERR ...` 应答或“请先登录”之类的客户端拒绝——
停留约 **8 秒**，并仅靠亮度和字重区分（白色边框和加粗白字），
因为页面外壳是灰阶的。最新的提示在最上面，最多同时显示 **5** 条，第 6 条会挤掉
最旧的。批量指令使用同一条提示，命令与应答两半用 ` · ` 连接各单位行。
快照差异事件（`建筑完成：…` / `遭到攻击：…`）使用同样的信息提示（没有命令半行），也会写入历史。

不会有任何丢失：右上角外壳中的小**日志**按钮会打开全屏历史浮层，按原顺序显示原始的
`#log` 文本。它有**关闭**按钮、清空历史与可见提示的**清空**操作，
可用 `Esc` 或点击背景关闭，并把焦点还给该按钮。状态行、
连接表单、HUD、命令栏以及 TypeScript 绑定的每个元素 id 都保持不变。

## LaTeX

任何标签、日志行、提示（toast）或悬停提示都可以包含行内数学 `$...$` 或独立公式 `$$...$$`。渲染使用
[KaTeX](https://katex.org/)（`katex@0.19.0`，已经是依赖）：`\$` 是字面美元符号、永不开始数学，
未闭合的 `$` 保持纯文本，`$$` 优先于 `$`，空的公式对按纯文本忽略。如果 KaTeX 不可用或抛出异常，
该片段回退为包含原文的**转义纯文本**，绝不会把异常抛给页面。KaTeX 只在第一次出现公式时通过
`await import("katex")` **懒加载**，因此从不显示数学的页面不会下载该库；只有
`katex/dist/katex.min.css`（连同 60 个字体文件）由 Vite 静态打包。数学继承周围外壳的颜色
（`color: inherit`），KaTeX 自己的红色解析错误颜色也被覆盖，因此灰阶外壳保持灰阶。不含 `$` 的
纯文本仍按原来的单个文本节点渲染，布局不会移动。

## 游戏视图

游戏视图现在铺满整页：一个 Canvas 2D 世界视图，所有面板都浮动其上。固定的
右侧协议栏已移除。HUD 在左上角，小地图在左下角，**命令栏**在
底部中央，**上下文面板**在右下角；右上角外壳承载常驻的状态
芯片、`工兵` 快捷按钮、**日志**、**资源**、**隐藏游戏画面** 以及小**连接**开关。表单里的
`connect`、`REGISTER`、`LOGIN`、`PING`、`COUNT`、`engine-info`、`hello` 和 `QUIT` 命令保持不变；它们和
`debug.key` 字段现在位于一个半透明浮层中，由**连接**打开，由**连接**或 `Esc` 关闭。该浮层的
容器透明，面板之外不接收指针输入，因此画布从不变暗，世界上的点击仍能到达画布。
交互以提示消息显示，完整历史仍可从**日志**按钮后查看。
没有安装任何新依赖：唯一的运行时依赖是已经安装好的 `katex` **^0.19.0**，两个 devDependencies 仍是 `typescript` 和 `vite`。

```shell
cd web-client
pnpm dev
```

直接打开 Vite 打印的地址即可；即使 Java 服务端未运行也能看到视图，只是连接
面板无法连接。右上角外壳中的**隐藏游戏画面 / 显示游戏画面**按钮会隐藏画布、HUD 和底栏，
并以旧的全页控制台角色打开连接面板；再次切换会重新关闭它。提示叠和
**日志**历史浮层在两种视图中都可用。（页面自身的界面目前是中文——`index.html` 中有
`lang="zh-CN"`——因此屏幕上的标签与这些英文名称不同。）

**三个底部区域。** 底栏是一个 CSS grid，因此三个区域永不重叠：

- **左下——小地图：** 同一块固定的 **180x180** 面板，使用自己的画布，点击/拖拽的相机
  映射与之前相同。它现在是第一个 grid 单元格，而不再是绝对定位的方块，但视觉上
  和行为上仍然是左下角。
- **底部中央——命令栏：** 上下文相关。未选中任何东西时只显示一行提示。选中单位
  时显示单位动作 **停止**（`ORDER STOP`）和 **攻击移动**（`ORDER ATTACKMOVE`，先激活再用
  下一次左键点击瞄准），以及**选中单位条**。每个芯片显示清单名称的前两个
  字符和一条细血条，血条颜色遵循与地面圆环和小地图圆点相同的归属规则（我的蓝色、
  敌方红色、中立灰色）；快照未报告生命值时血条为满。该条最多显示前 **12** 个
  选中单位的芯片，其余用一个 `+N` 芯片表示；点击某个芯片会把选择替换为仅该
  单位。命令栏始终显示当前提示 / 已激活模式提醒，选中工兵（一个**或多个**）时
  还会在上下文区域列出 **BUILD** 条目。
- **右下——上下文面板：** 选中自己的**同类型**建筑时显示该类型提供的 **TRAIN** 条目和生产队列
  列表（与之前相同的每项 `ticks / total` 行）；只有兵工厂训练单位，选中的矿井、伐木场或
  仓库完全不显示 TRAIN 区。选中多座同类型建筑时，一次点击会向**每一座**各排入同一个单位，
  它们并行生产；提示显示 `一次点击各排一个`。选中工兵组时显示 **BUILD** 条目；其他情况保持为空。
  敌方建筑的队列仍然显示，因为它是只读信息而不是动作。

**混合选择。** 同时包含至少一个己方单位**和**一座己方建筑的选择只提供单位
动作：提示显示 `混合选择只提供单位动作`，TRAIN/BUILD 被抑制。`TRAIN`（恰好一座建筑）和
`BUILD`（一名用于放置的工兵）都无法诚实地适用于混合编组，因此页面既不会悄悄挑一半，
也不会发送该选择并不支持的命令。这条纯粹的规则位于 [`src/render/commandbar.ts`](src/render/commandbar.ts)。

**较小的窗口。** 在 1280x720 及以上，三个区域互不接触，小地图和提示
叠也放得下：小地图是 180px 的 grid 列，提示叠被抬高到固定高度底栏之上。低于 **1100px** 时
小地图缩到 140px，上下文区域收窄到 220—280px；低于 **900px** 时 HUD 移到右上角
外壳下方，避免两者共用一行；低于 **760px** 时小地图隐藏，底栏把命令栏叠在
上下文区域之上（上下文区域内部滚动）；低于 **520px** 时右上角外壳 / HUD 使用整行宽度，仓库面板保留标记控件（面板本身保持自己的宽度）。在非常矮的视口（大约低于 520px 高）中，底栏保持
高度，面板内部滚动，提示叠仍在它上方原位；后面的画布
仍然可用，只是空间更小。

**单色外壳。** 页面外壳——面板、按钮、标题、HUD 芯片、日志、命令栏、上下文
面板、小地图边框和状态芯片——刻意采用灰阶，完全不带色相；错误状态是明亮的
白色文字加左侧白色竖条，而不是红色。画布是例外：它是游戏内容，因此保留自己的
颜色，小地图的地形、归属圆点和白色相机轮廓、建造放置预览的
绿/红/琥珀色地块以及芯片的归属色血条也是如此。每个浮动表面同样**半透明**：
HUD 芯片、单位库存面板、小地图面板、命令栏、上下文面板、仓库面板、
完整资源页、连接浮层的面板、悬停提示、提示叠和日志浮层面板都使用 `rgba(0, 0, 0, 0.72)` 和 1px 灰色边框，无模糊
也无发光（`backdrop-filter: none`），因此游戏视图在它们后面仍然可见。这些表面上的文字是 `#e6e6e6`
或白色，即使在最亮的地形上也能保持至少 7:1 的对比度，并且绝不会有遮罩或滤镜
盖在画布上——连接浮层和日志浮层的容器是透明的，只有它们的面板变暗。标签页
图标来自 [`oc.png`](public/oc.png)（从仓库根目录的 `oc.png` 原样复制），由 `index.html` 中的
`icon` 和 `apple-touch-icon` 链接引用。

HUD 固定在视图左上角，并实时显示：

- 世界来源：快照到达时显示 `世界：server · tick 42`，页面绘制内置回退地图时显示 `世界：demo`；
- 相机坐标和窗口原点：`坐标：1234,-567 · 窗口：1250,-582`。两者都可以为负，并随所有者平移持续计数；相机流式载入新窗口时窗口原点会变化。在演示地图上该芯片从 `坐标：2,16 · 窗口：,0` 开始（演示岛是原点为 `0,0` 的自有窗口）；
- 贴图来源：`atlas · oc-hello`（插件不超过三个时列出插件 id）、`atlas · 4 plugins`；回退到程序化绘制时为 `procedural`；
- `WHOAMI` 应答的引擎玩家 id（`玩家：`；登录前为 `玩家：未登录`，应答到达前为 `玩家：获取 id 中…`，每次重连时再次清空）。如果 WHOAMI 应答丢失，客户端还会用刚登录的账号名去快照 `players` 行里恢复 id；
- 来自 `players` 中 id 与 `WHOAMI` 匹配的那一行的本地玩家资源和收入速率：`资源：alice · 金 300 (+30/分) · 木 60 (+20/分)`。速率后缀来自 `goldPerMinute` / `woodPerMinute`，旧快照缺少这些字段时省略（新服务端报告零时显示 `+0/分`，以便操作者看出没有矿井在运行）。当世界还没有该玩家的行时——登录前、演示地图上，或面对快照没有 `players` 字段的旧服务端——该标签变灰并显示破折号（`资源：金 —· 木—`）；
- **已标记资源行**：仓库面板里勾选的物品显示为 `已标记：金 120 · 木 40`，没有标记时是 `已标记：—`。数量与仓库面板使用同一份合计，因此这一行和面板行不可能对不上；
- 鼠标下的地块坐标；
- 缩放倍率（0.5× 到 2.5×）；
- 平滑后的 FPS；
- 恰好选中一个实体时，该实体的 id、显示名称、归属标签和地面坐标（`选中：e12 普通[我] (12.5, 8.5)`）；本地玩家的标签是 `我`，其他玩家是 `敌`，无主实体是 `中立`，还不知道本地玩家 id 时明确显示 `未登录`。标签、命令栏动作和提示都读同一个判定，所以不会出现标签写 `我` 而命令栏说“不属于你”的情况。贴图清单没有该类型的名称时显示原始类型（`选中：e12 unit.melee.t1 [未登录] (12.5, 8.5)`），`选中：无` 表示没有选中任何东西。选中多个单位时同一芯片变为 `已选：3 个实体`，单实体详情和建筑芯片会被有意抑制；
- 恰好选中一个**己方单位**且其 `contents` 对象非空时，同一行会追加其货物：`· 携带：金 7 · 木 3`。物品名称优先取插件清单，其次取经典的 `金` / `木` 标签；清单不认识的路径保留原始路径。没有货物的单位（或没有 `contents` 的旧快照）完全不加内容，敌方单位也从不显示货物行。纯格式化器是 [`src/render/status.ts`](src/render/status.ts) 中的 `unitCargoLabel`；
- 选中建筑的显示名称和 id（`建筑：兵工厂 1 级 #42`），己方或敌方皆可，同样回退到原始类型（`建筑：building.armory.t1 #42`）。快照携带占地时，芯片会追加 `· 尺寸：3×3`，建筑在建期间还会用一个小内联条显示完成百分比（`▮42%`）。选中的仓库还会追加其库存物品，例如 `· 库存：金 120 · 木40`；只显示正数量，顺序固定为金/木。没有 `w`/`h`/`progress`/`contents` 的快照（旧服务端、演示世界）直接省略这些部分；
- 对选中的建筑，建筑芯片下方每个未完成生产任务占一小行：清单显示名称（清单无名称时为原始 `kind`）、细 `ticks / total` 条和从 1 开始的 `i/n`（`普通▮▮▮1/2`）。尚未开始的任务报告 `ticks === total`，因此其条从空开始。画布保留现有的 `生产中×N` 标记；有 `queue` 但没有 `queueItems` 的旧快照只显示该标记，没有逐项行。

**单位库存面板。** 在左上角 HUD 芯片正下方，另有一块始终可见、无需悬停的灰阶小面板，列出**选中单位的货物**：每个物品一行（清单显示名称与数量），一行 `合计：N`，选中的单位什么都没带时显示 `未携带任何物品`。选中一个单位时显示它自己的货物；选中多个单位时显示聚合货物和一行计数（例如 `3 个单位 · 2 个携带货物`）；没有选中单位时显示 `未选中单位`。建筑从不贡献货物（建筑的库存属于仓库面板）。聚合使用 [`src/render/resources.ts`](src/render/resources.ts) 中与仓库合计相同的 `sumContents` 规则，因此两个界面不可能用不同方式汇总同一批物品。它与 HUD 芯片一样不接收指针事件，绝不挡住画布。

**框选优先级。** 一次框选可能同时覆盖单位和建筑，因此选择遵循一条规则。在矩形覆盖的己方实体中，只选中**存在的最高优先级组**：

1. **战斗单位**——可选 `role` 为 `combat`、或可选 `attackDamage` 为正的己方单位；当前线上格式两者都不携带，因此改为从内容路径识别经典的 `unit.melee.*` 系列（以及演示中的 `soldier`）。同一次选择允许混合不同的战斗类型；
2. **建造单位**——己方工兵（`unit.engineer` / `engineer`，包括带命名空间的路径）；
3. **建筑**——己方建筑，且仅当完全没有覆盖任何己方单位时，因此只覆盖建筑的框选会选中其中的每一座己方建筑。

各组互斥：矩形内任何战斗单位都会压制所有建造单位和建筑，建造单位又压制所有建筑。敌方和中立实体永不符合条件，空框选不选中任何东西。纯规则是 [`src/render/selection.ts`](src/render/selection.ts) 中的 `selectByPriority`；[`src/render/view.ts`](src/render/view.ts) 中的 `marqueeSelection` 收集己方、窗口内的候选并应用它。普通点击保持旧规则（只点击建筑即可选中建筑），Shift+点击则无视该优先级添加或移除单位或建筑。

**双击选择。** 双击作用于整个已载入窗口，而不只是被点击的实体。双击单位会把选择替换为**所有同类、地面地块位于已载入窗口内的己方单位**（渲染器和拾取器使用的同一可见性规则）；双击**己方建筑**会把窗口内所有同类型己方建筑一起选中，因此一排兵营可以一次批量 TRAIN；双击敌方或中立建筑仍只选中它自己。它总是替换选择，从不合并。拖拽永远不算双击的一部分：结束框选的 mouseup，或跟随相机/实体拖拽的点击，都不能构成双击，且两次点击必须落在同一目标上、间隔 350 ms 内、移动不超过 6 px。

**悬停提示。** 游戏视图可见且指针停在实体上时，一个小提示会跟随光标。它是 DOM 元素而非画布：左侧是一个固定的 **48×48** 缩略图，然后是清单显示名称、**单独一行加粗的归属标签**（`归属：我` / `归属：敌` / `归属：中立` / `归属：未登录`）、生命百分比，若是建筑还显示上报的占地（`尺寸：3×3`）和队列摘要（`生产中×N`）。缩略图通过与世界渲染器相同的 `lookupAtlasEntity` 查找取实体的图集帧，所以小方块显示的就是地图上的那株；没有图集帧时变成一块中性灰方块，上面只有 **kind 的第一个字符**。画布固定为 48×48 CSS 像素，因此提示框文字行增减时缩略图不会引起重排；它也不接收指针事件，绝不抢点击。提示框与其他外壳一样是灰阶半透明，设置 `pointer-events: none`，在框选或 BUILD 放置激活期间保持隐藏，并被限制在浏览器窗口内（靠近边缘时翻到光标左侧或上方）。指针停在同一个实体上超过 **6 秒**后提示框会自行隐藏，以免长期挡住地图；换到另一个实体会重新计时，而在同一实体内抖动不会让它闪烁重现。`$...$` 公式升级为 KaTeX 后，提示框会重新测量并重新定位。没有 `health` / `w` / `h` / `queue` 的快照会省略这些部分，而不是编造数值。

**派生事件。** 服务端没有事件流，因此客户端比较相邻快照。一座原本未完工（`progress !== 1`）而现在报告 `progress === 1` 的建筑会提示 `建筑完成：<name>`；**本地玩家的**建筑或单位生命比例下降到至少低 10 个百分点时会提示 `遭到攻击：<name>（攻击者：tN）`，N 取四格内附近敌方近战单位中的最高等级（快照没有攻击者字段；括号里是明确的“附近敌人”推断，附近没有敌人时写 `未知`）。敌方单位掉血不会提示成“你的基地被攻击”。只比较两个快照中都存在的实体，且同一实体在五秒内去重，因此一场持续数个 500 ms 轮询的战斗不会每次轮询都提示。这完全在客户端完成——协议和服务端都不变。

**仓库面板与资源标记。** 视图右上角显示本地玩家的仓库总量：所有己方建筑的 `contents` 对象按物品求和，用物品显示名称标注并按名称排序。没有己方仓库时显示 `未发现自己的仓库`；空仓库报告空汇总。现在每个物品行都有一个**复选框**，表头还有 **标记全部** / **清除** 一对按钮。标记是**纯客户端状态**：勾选不会向服务端发送任何东西，跨快照保留（某个物品暂时为 0 时，已标记行仍显式显示 `0`），并在断线时随其余玩法身份一起清除。被勾选的物品显示为顶部外壳里的紧凑行 `已标记：金 120 · 木 40`，数量与面板使用同一份仓库合计。标记/取消标记、已标记总量和已标记行的纯规则位于 [`src/render/resources.ts`](src/render/resources.ts)。

**完整资源页。** 右上角的 `资源` 按钮打开一个半透明面板（再次点击该按钮关闭；`Esc` 和面板里的 **关闭** 按钮也能关闭），列出**这个世界里存在的每一种资源**：插件清单发布的物品定义（可选 `items` 表）、本地玩家任何建筑里的物品、其单位携带的物品，以及 `gold` / `wood` 两种货币。行按内容路径去重、按显示名称排序，没有库存的物品保留显式的 `0` 而不是被隐藏。每行显示拥有总量（玩家货币余额加上己方仓库和携带中的全部正数量）；如果物品放在建筑里，行内还会说明位置（`位置：建筑 #12`），只由单位携带的物品也会注明。面板容器透明且面板外不接收指针输入，所以画布上**没有遮罩**，世界保持可交互。

**工兵快捷方式。** 右上角的 `工兵` 按钮和 `O` 热键会选中已载入窗口内所有己方 `unit.engineer`，替换当前选择。快照不携带命令或忙碌状态，因此无法区分空闲工兵和正在工作的工兵：按钮刻意标为 `工兵` 而不是 `空闲工兵`，并且选中所有工兵，而不只是空闲的。

**归属圆环与单位标记。** 每个实体在其精灵下方还有一圈细地面圆环：`playerId` 是本地玩家时蓝色 `#3b82f6`，其他玩家时红色 `#ef4444`，归属缺失、为零或尚不知道 `myPlayerId` 时灰色 `#9ca3af`（整个演示地图都属于后者）。单位额外带一个标记，让混战中的归属不可能看错：己方单位身体外有一圈细亮**白色**描边，敌方单位脚下有一块半透明**红色**底环。两者都是画布内容，因此灰阶外壳规则仍然成立：白色无彩色，红色与归属圆环、小地图圆点使用同一个敌方红。建筑只保留圆环（给屋顶加白描边会被误读成选中，红色底环又会和施工条打架），归属由提示框的加粗归属行负责。金色选择圆环不变，绘制在额外标记之后并保持在上层。分类逻辑位于 `src/render/view.ts`（`ownershipOf`、`ownershipColor`、`ownerBadge`），因此圆环、额外标记与 HUD 标签不可能不一致。

**建造放置预览。** 建筑路径被激活期间，页面在点击前就用光标下的整块占地做预览：占地的宽高来自建筑类型（客户端不认识的类型按 **3x3** 处理，`src/render/placement.ts` 中的表镜像经典目录），悬停地块是占地的左上角地块，每个占地地块用三种状态之一绘制：

- **合法**——绿色轮廓加 25% 填充；
- **被阻挡**——红色轮廓和填充，因为某个占地地块在快照中不是可建造地形（只有 `grass` 和 `sand` 是），或位于已载入窗口之外，或已被某个实体的占地覆盖；
- **超出范围**——琥珀色轮廓和填充，因为选址离选中的工兵太远。

状态芯片在悬停时给出判定：`可建造`、`地形不可建`、`位置被占用`、`超出工兵范围 16 格` 或 `超出已载入窗口`。预览和点击共享同一个纯判定（`buildPlacementPreview`）：**只有合法选址才会发送 `BUILD`**；非法点击保持模式激活，报告原因（状态芯片、日志和错误提示）且不发送任何东西。各状态按文档顺序组合：**被阻挡 > 超出范围 > 合法**。距离检测是客户端对服务端规则的近似：服务端允许到占地一格宽接近环的路径最多 16 格（`CommandService.MAX_BUILD_PATH_TILES = 16`），而客户端只比较工兵地块与占地矩形之间的切比雪夫距离——16 格外的选址被接受，17 格则不被接受。该近似可能接受障碍物后的选址，但绝不会仅因距离拒绝服务端会接受的选址；服务端仍然校验一切。预览颜色是画布内容，与归属圆环完全一样：周围的面板、HUD 和状态芯片保持灰阶。

**小地图。** 游戏视图左下角有一块固定的 **180x180** 概览面板，使用自己的小画布。面板外壳是灰阶（1px 灰色边框、半透明 `rgba(0, 0, 0, 0.72)` 背景），只有其画布区域接收指针输入，因此世界视图的其余部分保持正常的鼠标、滚轮和键盘行为；游戏视图上没有遮罩也没有滤镜。内部，已载入窗口的地形按**每地块一个像素**绘制（离屏的按地块尺寸画布放大，禁用平滑），窗口内每个实体是一个 **2x2 圆点**，颜色遵循与地面圆环相同的归属规则（我的蓝色、敌方红色、中立灰色），相机的可见矩形是**白色 1px 轮廓**。在小地图上**点击或拖拽**可移动相机：点击点减去黑边偏移、除以每地块缩放并**向下取整**，然后加到有符号窗口原点上，因此对负世界坐标也精确；相机以该地板地块为中心，目标被钳制到相机使用的同一个 ±500,000 地块数值安全边界。地形图像只在窗口或其地形变化时重建，而圆点和相机矩形每个动画帧都会重绘。

**服务端世界。** 游戏视图不再局限于内置演示岛。视图可见期间，
`main.ts` 每 500 ms 轮询 `GET /world/snapshot?cx=<cameraTileX>&cy=<cameraTileY>&r=32`（上一个请求仍在
途中时跳过本次请求），并把最近两个快照作为帧保留，供动画循环在
其间插值（见下文**移动平滑**）。服务端世界是**无边界**的：一个快照只携带一个方形
窗口，`originX` / `originY` 是其绝对左上角地块，`width` / `height` 是**窗口**尺寸，实体
保留绝对世界坐标。文档不携带 `mapWidth` / `mapHeight`，也完全没有地图尺寸；窗口
原点和每个实体坐标都可以为负或非常大。`src/render/view.ts` 的
`fetchWorldSnapshot(baseUrl, request)` 把服务端 JSON 转换为渲染器已经
消费的同一个 `WorldView`：地形内容路径变成地形 id，`originX` / `originY` 保留为有符号整数，`health` 变成
`healthRatio`，`player` 变成 `playerId`，可选的 `players` 数组变成带类型的 `PlayerView` 行（没有
该字段的快照仍然有效，因此旧服务端可以继续工作）。可选实体详情字段也是
增量式的：`w` / `h` 变成 `footprint`，`progress` 变成被钳制的比例，`queue` / `queueTicks` 变成
生产队列大小和正在运行任务的剩余 tick，`queueItems` 变成经校验的 `kind` / `ticks` / `total` 任务
数组（格式错误的条目会被丢弃），`contents` 变成由正整数数量组成的经校验对象：
仓库在那里报告库存物品，携带单位以相同形状报告货物。
玩家行把可选的 `goldPerMinute` / `woodPerMinute` 保留为数字，或者
对旧服务端留作 `undefined`。缺少其中任何字段的快照与之前完全一样地转换；格式错误的
可选字段会被忽略，而不是拒绝整个世界。
`terrainAt` 翻译绝对地块时先
减去原点（先向下取整，因此负的小数位置会落进正确的单元格），并在窗口之外
返回 `void`；渲染器和实体拾取器只绘制或选中地块位于窗口内的实体。
行长度错误、缺少字段、坐标非有限或窗口原点非整数的文档会被拒绝——
但坐标为负或很远不是错误，因为不存在要跨越的地图边界。程序化的
`demoWorld(seed)` 完整保留为缺失快照时的回退（例如 `--world off`，它应答 503）。
标签页隐藏时定时器会在 `visibilitychange` 上取消，因此后台标签页不发送快照请求。
使用 `--http-port 0` 时不轮询任何东西，页面停留在演示地图上。

**由相机驱动的窗口流式加载。** 画面移动，客户端跟随：`main.ts` 维护一个相机焦点（相机的
中心地块），一旦它距已载入窗口边缘 8 格以内，就请求以该焦点为中心的新窗口，而不是
平移进尚未载入的地形。旧窗口留在屏幕上直到新窗口到达，因此加载期间既不变空白也
不闪烁；失败或被拒绝的请求保留最后一个窗口，而不是退回演示地图，单调递增的
请求 id 会让迟到的应答输给更新的请求。请求的中心按其原样发送，因此服务端对任何
有符号中心都应答原点 `centre - r`：不存在会向内钳制或平移窗口的地图边缘。

**世界是无边界的。** 客户端模型和相机中都没有地图宽度、高度或边界。
相机只被一个非常宽松的 **±500,000 地块安全边界**钳制（按 32 px/地块计算即 1600 万世界像素），
而且该边界不是玩法：它存在是因为引擎用单精度 `Vec2` 存储位置，其
分辨率在那个量级附近已经大约是一个世界像素。相机只构建一次，窗口到达时从不重建：
快照只改变载入哪块地形，不改变相机能去哪里。因此向任何方向平移都持续有效，
包括负坐标和远远超出出生点的位置。HUD 显示相机坐标和
已载入窗口原点（`坐标：1234,-567 · 窗口：1250,-582`），以便所有者观察两者变负并继续
计数。

**移动平滑。** 快照每 500 ms 才到达一次，因此每收到一个就绘制一次会让单位一顿一顿。视图现在
保留上一个和当前服务端帧（各自是转换后的 `WorldView` 加上其 tick），并在每个动画
帧用 [`src/render/interpolate.ts`](src/render/interpolate.ts) 中的
`interpolate(previous, current, alphaFor(now, currentFetchedAt, WORLD_POLL_MS))` 重绘。
两帧中都存在的实体做线性插值；只在新区出现的实体出现在其新位置；
消失的实体则消失；两次轮询之间移动超过 4 个地块、或类型/归属发生变化的实体
直接跳到新帧，而不是滑过地图。这多花一个轮询间隔的延迟——画面比最新快照晚一帧——
这是服务端仍然每 tick 发送绝对位置（协议不变）时获得平滑移动的代价。演示世界不受影响：
它没有快照，保持自己的动画时钟。启动后的第一个快照，以及不同流式窗口的第一个快照，
没有前驱，会直接绘制；标签页隐藏时轮询和动画循环都会停止。

### 操作

它们在第一次点击视图之后生效；键盘事件只绑定到画布，绝不会从协议输入框抢走按键。

| 操作 | 效果 |
| --- | --- |
| 左键点击 | 把选择替换为光标下的实体；点击空地则清空选择 |
| 双击单位 | 把选择替换为已载入窗口内**所有同类己方单位**。该类型的敌方/中立单位以及窗口外的同类单位都被排除 |
| 双击建筑 | 己方建筑：把选择替换为已载入窗口内所有同类型己方建筑（批量 TRAIN）；敌方或中立建筑：只选它自己。拖拽永远不算双击的一半，因此结束框选（或跟随拖拽）的点击不能构成双击 |
| 悬停实体 | 在光标附近显示灰阶 DOM 提示：左侧固定 48×48 的图集帧缩略图（没有图集帧时为带 kind 首字符的灰底占位符）、名称、单独加粗的归属行、生命值、建筑占地、队列摘要；框选或 BUILD 放置期间隐藏，在同一实体上停留 6 秒后自行隐藏 |
| 勾选仓库物品 | 只在客户端状态里标记该物品；复选框在右上角仓库面板，表头的 **标记全部** 勾选当前列出的全部物品，**清除** 清空所有标记 |
| `资源`（右上角外壳） | 打开完整资源页（清单物品 + 己方仓库物品 + 己方携带 + 两种货币，排序、保留 0）；该按钮、面板里的 **关闭** 和 `Esc` 都能关闭它 |
| Shift + 左键点击 | 添加被点击的实体，或在其已被选中时移除它。对单位**和建筑**都有效，不受框选优先级影响，并保持选择顺序 |
| 在空地上左键拖拽 | 绘制框选矩形并应用**选择优先级**：覆盖到己方战斗单位时选它们，否则己方建造单位（工兵），否则己方建筑。敌方和中立实体总被排除，只覆盖建筑的矩形会选中其中的每一座己方建筑。矩形从画布空间转换为世界地块，因此负坐标下也有效 |
| 从实体上开始左键拖拽 | 仍然选中该实体（永远不会变成框选） |
| 中键拖拽，或按住 Space + 左键拖拽 | 平移相机。空地上的左键拖拽是框选，因此不再平移 |
| 右键点击空地 | 对**每个选中的己方单位**发送 `ORDER MOVE <id> <tileX> <tileY>`，每个单位一行 |
| 右键点击不属于我的实体 | 对每个选中的己方单位发送 `ORDER ATTACK <id> <enemyId>` |
| 命令栏中的**攻击移动** | 激活攻击移动；下一次在画布上左键点击会为每个选中的己方单位发送 `ORDER ATTACKMOVE <id> <tileX> <tileY>`。按钮可再次切换关闭该模式，`Esc` 取消它，选择失去最后一个己方单位时该模式也会自行取消 |
| 点击选择芯片 | 把整个选择替换为仅该单位（等同于普通左键点击），因此芯片也是丢弃组内其余单位的快捷方式 |
| 滚轮 | 围绕光标缩放，保持光标下的地块固定 |
| 在小地图上点击或拖拽 | 把相机居中到指针下的地板地块，钳制到相机的数值安全边界。面板只拥有它的 180px 方块；其他地方世界画布保持正常输入 |
| `WASD` / 方向键 | 平移相机 |
| `+` / `-` | 围绕视图中心放大 / 缩小 |
| `F` | 把相机重置到起点和 1× |
| `O` | 选中已载入窗口内所有己方工兵（等同于右上角外壳中的 `工兵` 按钮）。快照没有命令状态，因此这是所有工兵，而不只是空闲的 |
| `Ctrl` + `1` —`9`（`Cmd` 也可以） | 把当前选择分配到该编队，替换编队原有内容。选择可以包含建筑；空选择会清空该编队 |
| `1` —`9` | 召回该编队。首先清理已死亡的实体 id；空编队会在状态行报告 `编队 N 为空`，而不是悄悄清空选择。选择来自该编队时，HUD 选择行会加上 `编队 N ·` 前缀 |
| `Shift` + `1` —`9` | 把当前选择加入该编队，不移除它原有的内容 |
| `Esc` | 取消已激活的 BUILD 放置或攻击移动；两者都未激活时清空选择。连接浮层打开时，`Esc` 先关闭该面板 |

每条命令路径共享同一份选择：渲染器在每个选中实体上绘制金色圆环，HUD 在选中多于一个时显示
`已选：N 个实体`，命令栏在至少选中一个己方单位时立即启用**停止**。**停止**为每个
这样的单位发送 `ORDER STOP <id>`，**攻击移动**在点击目标地块后为每个己方单位发送一行
`ORDER ATTACKMOVE <id> <x> <y>`。编队也是选择状态：纯 `assign` / `add` / `recall` / `prune` / `describe` 规则位于
[`src/controlGroups.ts`](src/controlGroups.ts)，页面在每次快照时清理编队，分配对
命令合法性而言是空操作——编队可以持有建筑，但只有正常的归属和单位检查才决定命令可以
指向什么。左键点击仍然先经过放置/攻击移动模式：`BUILD` 激活期间，画布上的下一次左键
点击放置选址且不改变选择；攻击移动激活期间，下一次左键点击发送
命令而不是选择，两种模式下空地上的左键拖拽都继续平移相机。

**选择闪烁。** 由玩家操作引起的选择变化——单击、Shift+点击、框选释放、双击、点击芯片、编队召回或 `工兵` 按钮——会让每个新选中的实体闪一次：约四分之一秒（[`src/render/flash.ts`](src/render/flash.ts) 中的 `FLASH_MS = 250`）的白色/浅灰（无彩色）光晕，画在精灵之上、金色选择环之下；客户端自己造成的选择变化（清理已死 id、切换到新快照窗口、重连后恢复选择）不会闪烁，快速重选也只为本次操作真正新增的实体重启光晕。

**底部命令栏及其右侧上下文区域**驱动其余语法。只有当选择属于 HUD 中的玩家 id
（`entity.playerId === myPlayerId`）时它们才启用命令，因此点击别人的单位
绝不会意外发送命令：

- **停止**为每个选中的己方单位发送 `ORDER STOP <selected>`；只要选择中包含一个就启用。
- **攻击移动**为每个选中的己方单位激活 `ORDER ATTACKMOVE <selected> <x> <y>`，并把画布上的下一次左键点击
  作为目标；按钮可切换关闭该模式，`Esc`（或选择失去所有己方单位）会取消它。
- `工兵`（热键 `O`，右上角外壳）是选择快捷方式而不是命令：它选中已载入窗口内
  所有己方 `unit.engineer`。快照没有命令/忙碌标志，因此无法只选空闲工兵；标签及其提示
  都写着 `工兵`，两个 README 都注明了这一限制。
- 命令栏中的**选中单位条**每个选中单位一个芯片，最多 12 个，之后是 `+N`。每个芯片显示
  清单显示名称的前两个字符，以及一条单位归属色的细血条；点击芯片
  会把选择替换为仅该单位。选中的建筑不是芯片（改由 HUD 芯片和上下文面板
  描述）。
- 选中己方**同类型**建筑时，**右下上下文区域**为每条目录中的单位路径（`unit.melee.t1`—`unit.melee.t5`、
  `unit.engineer`）显示一个 `TRAIN <buildingId> <unitPath>` 按钮，单选时后面跟着生产队列行。有清单显示名称时
  按钮文字就是它（经典单位为 `普通`、`强化`、`精英`、`将领`、`战王`、`工程师`），提示里保留原始路径；
  没有名称时回退到原始路径。当前兵工厂无法生产的等级仍会提供，服务端的 `ERR ...` 会
  显示在状态芯片和错误提示中。选中多座同类型建筑时，一次点击按选择顺序为每座各发一条 `TRAIN`，
  所有被选兵营同时排队；提示显示数量并说明并行生产。不同类型的建筑组不提供 TRAIN，并提示必须同类型。
- 选中己方工兵（恰好一个实体）时，同一上下文区域为每条目录中的建筑路径（`building.armory.t1`、
  `building.mine.t1`、`building.lumbercamp.t1`、`building.warehouse`）显示一个
  `BUILD <engineerId> <buildingPath> <tileX> <tileY>` 按钮。其文字是清单显示名称
  （`兵工厂1 级`、`矿井 普通`，清单提供时还有伐木场的自有名称），没有则是原始路径。按下其中一个会
  激活放置：状态芯片显示模式，光标下的整块占地会用绿色合法 / 红色被阻挡 / 琥珀色超出范围的地块
  预览，并在悬停时给出原因，只有**合法**选址才让画布上的下一次左键点击发送命令；随后模式清除。
  非法点击保持模式激活，报告 `地形不可建`、`位置被占用`、`超出工兵范围 16 格` 或 `超出已载入窗口`，
  且不发送任何东西。`Esc` 取消但不会取消选中工兵。16 格检查是客户端对服务端 16 格路径规则的
  距离近似；见上文**建造放置预览**。
- 至少一个己方单位加一座己方建筑的**混合选择**只显示单位动作和芯片；提示
  为 `混合选择只提供单位动作`，上下文区域保持为空。既不是己方单位组、也不是同类型己方建筑的选择
  （敌方实体、不同类型的多座建筑）不提供动作，并在提示行说明原因。

`WHOAMI` 在 `LOGIN` 之后自动发送（新登录时也如此），其 `OK player <id>` 应答被解析到 HUD 字段。每个玩法命令和应答都出现在日志浮层中并作为交互提示显示（编队命令是一条提示，命令和应答两半连接各单位行）；`ERR ...` 应答变成错误提示，也会原样显示在状态芯片中，而成功会得到一条使用显示名称并保留括号中原始 id 的简短确认，例如 `已下训练 普通(unit.melee.t1)` 或 `已在 20,40 下达 BUILD 兵工厂1 级(building.armory.t1)`。线上命令本身不变，仍然携带 `unit.melee.t1` / `building.armory.t1`。目录位于 [`src/commands.ts`](src/commands.ts)，并附有服务端拥有真相的注释：在服务端添加内容意味着也要更新该列表。线上格式接收整块地块索引；引擎把 `GridPos` 解释为该地块的中心。

**贴图由插件提供**：每个插件把自己的 `assets/manifest.json` 和图片打包进自己的 jar，服务端把它们合并到
`GET /plugin-assets/manifest.json`，客户端在启动时读取它，并按每个图片的 `atlasUrl` 加载。多个插件同时提供贴图时，它们按数组顺序合并，
**后者覆盖前者**（同名地形路径或实体类型，包括显示名称）。本地 `public/textures/atlas.json` 不再是来源；该目录只保留
[契约文档](public/textures/README.md)（清单格式、示例、脚部锚点、每个实体一行动画）。

清单也可以携带**显示名称**：动画字段旁的 `entities.<kind>.name`，以及地形块的名称——
既可写成命名对象形式 `tiles.<path>: {"rect": [x, y, w, h], "name": "草地"}`，也可在旧式数组形式中完全不写。客户端
把名称与帧合并（后者插件获胜），HUD、TRAIN/BUILD 按钮标签以及成功状态/提示行都会使用它们；
名称缺失或为空时总是回退到原始内容路径，因此没有名称的清单行为与之前完全一致。名称仅用于
显示：协议命令仍然发送内容路径。
当清单缺失、请求失败、图片加载失败或响应为 `[]` 时，客户端自动回退到程序化绘制：每种地形类型有自己的颜色和细节，
单位是圆形，建筑是带屋顶线的方块，缩放较大时有 1 像素网格。同一遍绘制还会在建筑上方绘制
灰阶状态外壳：未完工时一条细施工条（浅灰轨道、白色填充、1 像素边框），
生产队列非空时一个小 `生产中×N` 标记。两者都在
屋顶之上，因此从不遮住精灵。

> 初始地图是确定性的 `demoWorld(seed)` 占位物。一旦 Java 服务端应答
> `/world/snapshot`，视图就切换到那个真实引擎世界：无边界世界，一次一个 64 x 64 窗口，
> 跟随相机；渲染层不变，因为两个来源使用相同的 `WorldView` 形状。

渲染数学和纯客户端规则（相机的地板语义和 ±500,000 地块数值安全边界、
以光标为中心的缩放、占位地图的确定性、无边界有符号快照解析、负原点窗口
转换、8 格相机驱动窗口触发、有符号窗口原点和请求排序、快照
插值与跳变、越界图集帧的拒绝、清单显示名称与原始 id 回退、
磁盘上的经典清单、插件图集合并与回退、心跳常量/启动规则、框选
矩形到负地块的转换、框选选择优先级（战斗 > 建造 > 建筑，排除敌方和
中立，空矩形为空）与 `selectByPriority`、单位和建筑的 Shift+点击切换、提示

`footprint` / `progress` / `queue` / `queueTicks` / `contents` 字段）、仓库库存标签、单位货物标签
（`携带：…` 覆盖一个物品、两个物品、无物品以及未知路径回退到原始路径）、建筑目录（包括 `building.lumbercamp.t1` 和 `building.warehouse`）、建造放置预览（经典 3x3
占地图查找及未知类型 3x3 默认、行优先占地图块、来自实体列表的占用、16 和 17 格处的距离边界、被阻挡 > 超出范围 > 合法的优先级以及五条原因文本）、小地图（等比适配布局、双向基于地板的 panel-to-world 映射（包括负原点）以及安全边界相机跳转）、双击同类规则（仅己方、仅窗口内、建筑情形）、工兵选择规则、提示文本组合、固定 48×48 缩略图选择（图集帧 vs. 带 kind 首字符的灰底占位符）和停留隐藏 / 窗口钳制规则、快照差异事件（10% 生命下降阈值和每实体五秒去重）、仓库总量聚合、客户端标记/取消标记 / 标记全部 / 清除规则与 `已标记：…` 行、单个 / 多个 / 无单位的库存聚合、完整资源页合并（清单物品 + 仓库物品 + 携带 + 货币，去重、排序、显式 0、仅己方数量）、LaTeX 拆分器（纯文本 / 一个或两个行内公式 / 独立公式 / 转义或未闭合的美元 / 空公式对 / 混合，且不含美元时恰好一个纯文本片段）、转义纯文本回退与真实 KaTeX 渲染，以及命令栏（无选择 / 单位 / 工兵 / 建筑 / 混合单位加建筑选择及其仅单位动作规则的动作集、12 芯片上限和 `+N` 溢出、单字符和数字开头名称的两字符芯片缩写，以及 0 / 50 / 100 % 的血条比例，未报告视为满）都可以离线检查：

## hello 插件示例

`hello` 是示例插件 `oc-hello` 提供的请求，用来演示“插件应答请求”的最小闭环。它不需要 `debug.key`，
但和每个 `REQ` 一样，它需要先 `LOGIN`。它只应答一句问候，不读写任何游戏状态。

构建插件 jar，放进服务端的插件目录，启动服务端，然后启动浏览器客户端：

```shell
./gradlew --offline :projects:oc:oc-game-server-hello:jar
# copy projects/oc/oc-game-server-hello/build/libs/oc-game-server-hello-2.0a.jar into plugins/
./gradlew --offline :projects:oc:oc-game-server:server
# then, in web-client/:
pnpm install && pnpm dev
```

`oc-game-server-hello-2.0a.jar` 是 `version = '2.0a'` 模块的默认产物名；如果 Gradle 生成不同的名字，
以 `projects/oc/oc-game-server-hello/build/libs/` 中的文件为准。

该 jar 还携带 `assets/manifest.json` 和一个 128x128 的 `assets/atlas.png`（8x8 个 16x16 单元格）：jar 在 `plugins/` 中且服务端已启动时，
浏览器视图会自动从该图集渲染全部七条地形内容路径——`water`、`sand`、`grass`、`forest`、`hill`、`rock`、`void`。清单包含 20 个地块矩形（16 个美术地块加上 `forest`、`hill`、`rock`、`void` 四个别名键）和空的 `entities`，因此单位回退为程序化形状。这一步演示了从 jar 中的插件资源到服务端路由再到屏幕的完整链路。
不需要把任何图片放进 `public/`。

`plugins/` 是操作者的投放区：插件 jar 及其依赖的 jar 都放在这一层；见
[`plugins/README.md`](../plugins/README.md)。插件生成的状态位于服务端的 `data/` 下，而不是 `plugins/` 中。
第一次 `pnpm install` 需要网络；之后 `pnpm dev` 可离线工作。

页面把名称编码为 UTF-8 再 base64（标准字母表，带 `=` 填充）；服务端把请求载荷解码为原始字节交给插件，
然后把插件返回的字节做 base64 编码；浏览器最终把回复解码为 UTF-8 文本。`oc-hello` 自己不做 base64，
也不添加信封。超过 64 字节的名称会被插件截断并追加省略号。

## 构建

```shell
pnpm build
```

`build` 运行 `tsc --noEmit && vite build`，输出在 `web-client/dist/`。Java 服务端在
`http://<host>:25567/` 上提供这个静态构建。构建后可用下面的命令在本地预览：

```shell
pnpm preview
```

`pnpm install` 会创建 `node_modules/` 和锁文件；`node_modules/`、`web-client/dist/` 和
`web-client/.vite/` 已在 `.gitignore` 中。第一次安装需要网络，这是整个仓库中唯一会下载依赖的步骤。

## `debug.key`

- 首次启用 `oc-debug` 插件时，服务端生成 `<data directory>/oc-debug/debug.key`，默认为 `data/oc-debug/debug.key`。
- 其内容是 64 个十六进制字符，即 32 字节 AES-256 密钥；可能以换行结尾。
- 操作者**手动**把该文件复制到运行浏览器的机器，然后粘贴到页面上的文本框。密钥不通过 HTTP/WebSocket 传递，也不由页面生成。
- 服务端**从不覆盖**该文件；删除它并让插件重新生成会一次性使所有旧副本失效。
- 不要把 `debug.key` 提交到仓库、粘贴到 issue 或写入日志。
- `engine-info` 信封有 60 秒的防重放窗口，因此两台机器之间超过 60 秒的时钟差会使其失败。

`engine-info` 使用 `crypto.subtle`。浏览器只在**安全上下文**中提供它：`http://127.0.0.1:25567/` 和
`http://localhost:5173/` 没问题；直接用 `http://<LAN IP>:25567/` 打开页面通常不行，因此请用 localhost、
SSH 端口转发或 HTTPS 反向代理。

## 游戏命令与连接浮层

连接浮层仍然只提供 `PING`、`COUNT`、`REGISTER`、`LOGIN`、`REQ engine-info`、`REQ hello` 和
`QUIT`；除了 `REGISTER` 创建账号，这些都不会改变游戏状态。底部命令栏及其
上下文区域发送服务端的玩法语法——`WHOAMI`、`ORDER`、`BUILD` 和 `TRAIN`——它**确实**会改变
世界：指令移动和战斗，`BUILD` 放置并支付一个选址，`TRAIN` 排入一个单位。每个玩法
命令都要求同一连接上成功 `LOGIN`，并由服务端针对归属、
实体存在性、所提供的内容和玩家库存进行校验。页面从不改变服务端配置、
插件目录或账号的密码/权限。

- `engine-info` 是 `oc-debug` 注册的只读报告；处理器不持有可写引用，报告由常量和临时对象组装而成。
- `hello` 是 `oc-hello` 注册的只读问候；处理器只从请求中读取名称，不持有引擎、配置或网络引用。
- `REGISTER` 只创建新账号（重名会得到 `ERR …`）；它不会登录，也不会改变现有账号的密码或权限。
- `LOGIN` 只标记本连接的身份并刷新服务端记录的最近登录时间；它不改变密码、不改变权限，也没有修改密码的入口。
- `WHOAMI`（惰性地）分配并报告本连接的引擎玩家 id；它本身不改变任何游戏状态。
