## A. Ordinals and the googology library

- [x] **1. BMS ordinals.** Add BMS ordinals into `:projects:oc:oc-googology`, note that for every standard form BMS formula, the ordinal it represents can be compared using lexicographical order. For example, BMS formula $A=BMS(0)(1,1)$ and $B=BMS(0)(1)(2)$ are all standard form, and we can find out $A>B$ because the second column of $A$ is $(1,1)$ and the second column of $B$ is $(1)$, which means $(1,1)>(1)$ thus $A>B$. But do note, $B=BMS(0)(1)(2)=BMS(0,0)(1,0)(2,0)=BMS(0,0,0)(1,0,0)(2,0,0)=$, for $C=BMS(0)(1,0)$ we have $(1,0)>(1)$ but it doesn't means $C>B$, instead we have $B>C$. — *implemented as the `bms` package: `BmsMatrix` keeps the canonical short form, `BmsOrdinal` compares standard forms by the reference's lexicographic rule (`BmsOrder`, including the trailing-zero convention the paragraph above warns about) and expands them by the bad-root rules. The article, `BmsOrdinal` and `BmsMatrix` are cross checked against Cantor normal form in the googology self check (774).*

## N. Server-initiated NOTIFY push frames over the game WebSocket (2026-11-14)

- [x] **71. Push rarely-changing facts to the client the moment they change.** Owner requirement (design A approved): "把不常变化的数据在变化那一刻推给客户端，而不是等下一次快照轮询" — the per-session game WebSocket gains a server-initiated push frame `NOTIFY {"type":"contentVersion","value":N}`. — *inversion seam: new interface `world/NotificationBroadcaster.java` (`@FunctionalInterface`, one `broadcast(String frame)` method; strict contract: non-blocking, never throws, never calls back into the world, because it is invoked on the world thread holding `stateLock`); `WorldHost` keeps a `CopyOnWriteArrayList` of broadcasters (`addNotificationBroadcaster`, registration any time before/after `start()`; a frame broadcast before any registration is silently dropped — harmless, the frame is only a hint) and the `Events.DimensionAdded` handler calls `broadcastContentVersion()` after bumping `contentVersion` and dropping the caches: the frame bytes are built once per bump (`WorldHost.NOTIFY_FRAME_PREFIX = "NOTIFY "` + compact JSON `{"type":"contentVersion","value":N}`) and handed to every broadcaster inside a per-broadcaster try/catch, so a broken observer can never break the world thread. Receiver: `CommandWebSocketHandler implements NotificationBroadcaster`, registered into the host in `OcGameServer.start()` (the handler owns the greeted-session registry; `HttpWebServer` stays a transport adapter and is deliberately not the broadcaster — pushing game frames from the raw connection set would bypass the game protocol layer). Audience: every session that completed the HELLO handshake, logged in or not (contentVersion is not sensitive — the same value rides the unauthenticated snapshot route); a session still inside the handshake is never pushed because its `pushSocket` field is published only AFTER the `OK OC/1` answer was written, so the first frame a client sees is always its handshake answer and the server never pushes before OC/1 was agreed. Robustness: `broadcast()` only enqueues one task on a dedicated daemon single-thread executor (`oc-ws-push`, unbounded `LinkedBlockingQueue` so enqueueing from the world thread can never block, core thread times out after 30s idle so a handler costs no thread when quiet); the task walks the concurrent session map and isolates every send in its own try/catch — a dead session throws (IllegalState/UncheckedIOException), costs only its own frame and is closed by the failure path; a slow-but-open peer cannot block the world thread by construction, and its own idle read timeout eventually closes the socket, which unblocks a stalled writer. Semantics: the frame is a wake-up HINT, not state — no replay (a session connecting after the bump reads the version from its first snapshot/bootstrap), no queueing, no ack; the snapshot's `contentVersion` handshake remains the authoritative fallback, so a client that ignores NOTIFY entirely loses only latency. Frame registry is extensible: `type` selects the payload (future: plugin reload, world restart); unknown type = client ignores the frame; `NOTIFY` is the only unsolicited TEXT shape the server sends. Docs: protocol en+zh gained "Server-initiated NOTIFY frames" (+`contentVersion` type subsection) with the client contract — route inbound TEXT frames by the `NOTIFY ` prefix, it is NOT a command answer and must not consume a pending answer slot, on receipt act exactly like the snapshot-mismatch handshake (fetch `/world/bootstrap` ONCE, no loop, failure tolerances unchanged) — plus a compatibility bullet (additive server-to-client change, client routing obligation is the coordinated part) and a cross-reference from both bootstrap sections; Transport table answer row amended.
